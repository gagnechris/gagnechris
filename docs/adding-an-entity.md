# Adding an entity

Two kinds: a synced, owner-scoped Notebook entity (below), and a
[publishable site entity](#publishable-site-entity) with a draft, a live
snapshot and static public pages (like posts and projects).

How to add a synced, owner-scoped, versioned Notebook entity (like notes and tasks) to the API. The examples use a `bookmark` entity with `url` and `title`; replace the names.

The entity gets:

- `GET/POST /api/notebook/bookmarks`, `GET/PUT/DELETE /api/notebook/bookmarks/{id}`
- optimistic concurrency (`version`, `If-Match` / `ETag`, 409 / 412), client-ULID idempotent create, soft delete
- a `bookmark` change type in `GET /api/notebook/sync/changes`
- OpenAPI types in `@gagnechris/api-client`

No new GSI, table, or infra change is needed: META rows live in the existing table, and the sync GSI is shared.

## 1. Wire schemas — `packages/shared/src/schemas.ts`

Add the entity, list response, create / update / list-query schemas, and a sync change variant. Add the variant to `SyncChangeSchema`; `SYNC_CHANGE_TYPES` is derived from it.

```ts
export const BookmarkSchema = z.object({
  id: UlidSchema,
  userId: z.string().min(1),
  url: z.string().url(),
  title: NotebookTitleSchema,
  version: z.number().int().nonnegative(),
  createdAt: z.string().datetime({ offset: true }),
  updatedAt: z.string().datetime({ offset: true }),
  deleted: z.boolean(),
});
export type Bookmark = z.infer<typeof BookmarkSchema>;

export const BookmarkListResponseSchema = z.object({
  items: z.array(BookmarkSchema),
  nextCursor: z.string().min(1).optional(),
});

export const CreateBookmarkRequestSchema = z.object({
  id: UlidSchema,
  url: z.string().url(),
  title: NotebookTitleSchema.default(''),
});
export type CreateBookmarkRequest = z.infer<typeof CreateBookmarkRequestSchema>;

// `version` is optional because `If-Match` can carry it instead.
export const UpdateBookmarkRequestSchema = z.object({
  version: z.number().int().nonnegative().optional(),
  url: z.string().url().optional(),
  title: NotebookTitleSchema.optional(),
});
export type UpdateBookmarkRequest = z.infer<typeof UpdateBookmarkRequestSchema>;

export const ListBookmarksQuerySchema = z.object({
  cursor: z.string().min(1).optional(),
  limit: z.coerce.number().int().positive().max(100).optional(),
});
export type ListBookmarksQuery = z.infer<typeof ListBookmarksQuerySchema>;

export const BookmarkSyncChangeSchema = syncChangeSchemaFor(
  'bookmark',
  BookmarkSchema,
);

export const SyncChangeSchema = z.discriminatedUnion('type', [
  NoteSyncChangeSchema,
  TaskSyncChangeSchema,
  BookmarkSyncChangeSchema,
]);
```

Declare `BookmarkSchema` after `NotebookTitleSchema` / `NotebookTextSchema` (they are `const`s, not hoisted). Request text fields use `NotebookTextSchema` / `NotebookTitleSchema` / `NotebookTagsSchema` so oversized fields return 413.

## 2. OpenAPI — `packages/shared/src/openapi.ts`

Import the schemas, register the named components next to the other Notebook ones, and register the paths:

```ts
registry.register('UpdateBookmarkRequest', UpdateBookmarkRequestSchema);

registerNotebookEntityPaths(registry, {
  path: '/api/notebook/bookmarks',
  noun: 'bookmark',
  entity: BookmarkSchema,
  listQuery: ListBookmarksQuerySchema,
  listResponse: BookmarkListResponseSchema,
  createRequest: CreateBookmarkRequestSchema,
  updateRequest: UpdateBookmarkRequestSchema,

```

`registerNotebookEntityPaths` registers list, create, get, update (with `If-Match`), and soft delete with the standard responses. Paths beyond those go in `extraPaths` (see the notes and tasks calls).

Then run `npm run openapi` to regenerate `packages/shared/openapi/openapi.json` and `packages/api-client/src/schema.d.ts`.

## 3. Keys — `packages/data/src/keys.ts`

```ts
export function bookmarkPk(userId: string, bookmarkId: string): string {
  return `USER#${userId}#BOOKMARK#${bookmarkId}`;
}

/** GSI1 list partition: one per user. */
export function bookmarksGsi1Pk(userId: string): string {
  return `USER#${userId}#BOOKMARKS`;
}

export function bookmarkGsi1Sk(updatedAt: string, bookmarkId: string): string {
  return `UPDATED#${updatedAt}#BOOKMARK#${bookmarkId}`;
}
```

Key strings come only from these functions. An item key (`{ pk, sk }`) comes only from `keys`, so add one under `keys.notebook`:

```ts
bookmark: {
  meta: (userId: string, id: string) => ({
    pk: bookmarkPk(userId, id),
    sk: SK_META,
  }),
},
```

Partition keys start with `USER#<sub>#` so rows are owner-scoped. Lists use the existing `gsi1pk`/`gsi1sk` (or `gsi2pk`/`gsi2sk`) attributes, namespaced by `USER#<sub>#` so they never share a partition with posts or other users. The repository strips these four attributes from tombstones, so lists never return deleted rows.

## 4. Stored item — `packages/data/src/items.ts`

```ts
export const BookmarkMetaItemSchema = VersionedMetaFieldsSchema.extend({
  pk: z.string().min(1),
  sk: z.string().min(1),
  entityType: z.literal('bookmark'),
  id: z.string().min(1),
  userId: z.string().min(1),
  url: z.string(),
  title: z.string(),
});
export type BookmarkMetaItem = z.infer<typeof BookmarkMetaItemSchema>;

export function parseBookmarkMetaItem(raw: unknown): BookmarkMetaItem {
  return BookmarkMetaItemSchema.parse(raw);
}

export function metaToBookmark(item: BookmarkMetaItem): Bookmark {
  return {
    id: item.id,
    userId: item.userId,
    url: item.url,
    title: item.title,
    version: item.version,
    createdAt: item.createdAt,
    updatedAt: item.updatedAt,
    deleted: item.deleted,
  };
}

export function buildBookmarkMetaItem(b: Bookmark): BookmarkMetaItem {
  return {
    ...keys.notebook.bookmark.meta(b.userId, b.id),
    entityType: 'bookmark',
    id: b.id,
    userId: b.userId,
    url: b.url,
    title: b.title,
    version: b.version,
    createdAt: b.createdAt,
    updatedAt: b.updatedAt,
    deleted: b.deleted,
    ...(b.deleted
      ? {}
      : {
          gsi1pk: bookmarksGsi1Pk(b.userId),
          gsi1sk: bookmarkGsi1Sk(b.updatedAt, b.id),
        }),
  };
}
```

`VersionedMetaFieldsSchema` already allows `version`, timestamps, `deleted`, `createHash`, sync keys, `ttl`, and the GSI1/GSI2 attributes. Sync keys, `createHash`, and `ttl` are written by the repository, not by `build…MetaItem`. Import `Bookmark` from `@gagnechris/shared` and `keys`, `bookmarksGsi1Pk`, `bookmarkGsi1Sk` from `./keys.js`.

## 5. Repository — `services/api/src/bookmarks/repository.ts`

Wrap a `VersionedRepository` with the `ownerScoped` strategy. All concurrency, idempotent create, sync stamping, and soft delete come from the base; the wrapper maps requests to entities.

```ts
import type { DynamoDBDocumentClient } from '@aws-sdk/lib-dynamodb';
import {
  GSI1_NAME,
  bookmarksGsi1Pk,
  buildBookmarkMetaItem,
  keys,
  metaToBookmark,
  parseBookmarkMetaItem,
  type BookmarkMetaItem,
} from '@gagnechris/data';
import {
  BookmarkSyncChangeSchema,
  type Bookmark,
  type CreateBookmarkRequest,
  type ListBookmarksQuery,
  type SyncChange,
  type UpdateBookmarkRequest,
} from '@gagnechris/shared';
import { getDocClient, requireTableName } from '../data/client.js';
import { systemClock, type Clock } from '../data/clock.js';
import { hashCreateFields } from '../data/create-hash.js';
import { GSI1_CURSOR_KEYS } from '../data/cursor.js';
import {
  VersionedRepository,
  ownerScoped,
  type OwnerKey,
} from '../data/versioned-repository.js';

export const BOOKMARK_CHANGE_TYPE = 'bookmark';

export function bookmarkCreatePayloadHash(
  b: Pick<Bookmark, 'userId' | 'url' | 'title'>,
): string {
  return hashCreateFields([b.userId, b.url, b.title]);
}

export function bookmarkToChange(
  item: Record<string, unknown>,
): SyncChange | undefined {
  if (item.entityType !== BOOKMARK_CHANGE_TYPE) return undefined;
  let entity: Bookmark;
  try {
    entity = metaToBookmark(parseBookmarkMetaItem(item));
  } catch {
    return undefined;
  }
  return BookmarkSyncChangeSchema.parse({
    type: BOOKMARK_CHANGE_TYPE,
    id: entity.id,
    version: entity.version,
    deleted: entity.deleted,
    updatedAt: entity.updatedAt,
    ...(entity.deleted ? {} : { entity }),
  });
}

export class BookmarksRepository {
  private readonly base: VersionedRepository<
    Bookmark,
    BookmarkMetaItem,
    OwnerKey
  >;

  constructor(
    doc: DynamoDBDocumentClient = getDocClient(),
    tableName: string = requireTableName(),
    private readonly nowIso: Clock = systemClock,
  ) {
    this.base = new VersionedRepository(
      {
        conflictLabel: 'bookmark',
        scope: ownerScoped<Bookmark>({
          keyForId: (userId, id) => keys.notebook.bookmark.meta(userId, id),
          idOf: (b) => b.id,
          userIdOf: (b) => b.userId,
        }),
        toEntity: (item) => metaToBookmark(parseBookmarkMetaItem(item)),
        toItem: buildBookmarkMetaItem,
        isDeleted: (b) => b.deleted,
        nowIso: this.nowIso,
        sync: {
          changeType: BOOKMARK_CHANGE_TYPE,
          userIdOf: (b) => b.userId,
          createPayloadHash: bookmarkCreatePayloadHash,
        },
      },
      doc,
      tableName,
    );
  }

  getOrThrow(userId: string, id: string): Promise<Bookmark> {
    return this.base.getOrThrow({ userId, id });
  }

  createFromRequest(
    userId: string,
    body: CreateBookmarkRequest,
  ): Promise<Bookmark> {
    const now = this.nowIso();
    return this.base.createIdempotent({
      id: body.id,
      userId,
      url: body.url,
      title: body.title,
      version: 1,
      createdAt: now,
      updatedAt: now,
      deleted: false,
    });
  }

  updateFromRequest(
    userId: string,
    id: string,
    expected: number | 'any',
    body: Omit<UpdateBookmarkRequest, 'version'>,
  ): Promise<Bookmark> {
    return this.base.mutateIfVersion({ userId, id }, expected, (b, now) => ({
      ...b,
      url: body.url ?? b.url,
      title: body.title ?? b.title,
      updatedAt: now,
    }));
  }

  deleteIfVersion(
    userId: string,
    id: string,
    expected: number | 'any',
  ): Promise<Bookmark> {
    return this.base.softDeleteIfVersion(
      { userId, id },
      expected,
      (b, now) => ({
        ...b,
        updatedAt: now,
        deleted: true,
      }),
    );
  }

  list(
    userId: string,
    query: ListBookmarksQuery,
  ): Promise<{ items: Bookmark[]; nextCursor?: string }> {
    const pk = bookmarksGsi1Pk(userId);
    return this.base.queryPage({
      IndexName: GSI1_NAME,
      KeyConditionExpression: 'gsi1pk = :pk',
      ExpressionAttributeValues: { ':pk': pk },
      cursor: query.cursor,
      limit: query.limit,
      cursorKeyNames: GSI1_CURSOR_KEYS,
      cursorPartition: { attr: 'gsi1pk', value: pk },
    });
  }
}

let defaultBookmarksRepo: BookmarksRepository | undefined;

export function bookmarksRepository(): BookmarksRepository {
  defaultBookmarksRepo ??= new BookmarksRepository();
  return defaultBookmarksRepo;
}
```

`cursorPartition` makes a cursor from another partition a 400.

Repository options worth knowing:

- `uniqueClaim` — extra uniqueness rows in the create transaction, with conflict resolution and release on delete (daily notes use it).
- `cursorKeysByIndex` — default cursor keys per `IndexName` when a repository queries several indexes.
- `nowIso` — the only clock (a `Clock` from `data/clock.ts`, default `systemClock`); update and tombstone timestamps come from it, so tests inject a fixed clock.

## 6. Routes — `services/api/src/bookmarks/handlers.ts`

Reads and creates use `defineRoute`; every versioned mutation uses `versionedMutationRoute`, which resolves `If-Match` / `body.version` (400 when missing), maps conflicts (412 for `If-Match`, 409 otherwise), and returns the entity with its `ETag`.

```ts
import { z } from 'zod';
import {
  BookmarkListResponseSchema,
  BookmarkSchema,
  CreateBookmarkRequestSchema,
  ExpectedVersionRequestSchema,
  ListBookmarksQuerySchema,
  UlidSchema,
  UpdateBookmarkRequestSchema,
  type Bookmark,
} from '@gagnechris/shared';
import { jsonEntity, versionedMutationRoute } from '../data/versioned-route.js';
import { json } from '../http.js';
import { defineRoute, type RouteDef } from '../router.js';
import { bookmarksRepository, type BookmarksRepository } from './repository.js';

const IdParams = z.object({ id: UlidSchema });
const parseBookmark = (b: Bookmark): Bookmark => BookmarkSchema.parse(b);

export function createBookmarkRoutes(repo?: BookmarksRepository): RouteDef[] {
  const bookmarks = () => repo ?? bookmarksRepository();
  return [
    defineRoute({
      method: 'GET',
      pattern: '/notebook/bookmarks',
      auth: 'notebook',
      metric: 'ListBookmarks',
      query: ListBookmarksQuerySchema,
      handler: async (ctx, { query }) => {
        const page = await bookmarks().list(ctx.userId!, query);
        return json(
          200,
          BookmarkListResponseSchema.parse({
            items: page.items.map(parseBookmark),
            ...(page.nextCursor ? { nextCursor: page.nextCursor } : {}),
          }),
        );
      },
    }),
    defineRoute({
      method: 'POST',
      pattern: '/notebook/bookmarks',
      auth: 'notebook',
      metric: 'CreateBookmark',
      oversizedBody413: true,
      body: CreateBookmarkRequestSchema,
      handler: async (ctx, { body }) =>
        jsonEntity(
          201,
          await bookmarks().createFromRequest(ctx.userId!, body),
          parseBookmark,
        ),
    }),
    defineRoute({
      method: 'GET',
      pattern: '/notebook/bookmarks/:id',
      auth: 'notebook',
      metric: 'GetBookmark',
      params: IdParams,
      handler: async (ctx, { params }) =>
        jsonEntity(
          200,
          await bookmarks().getOrThrow(ctx.userId!, params.id),
          parseBookmark,
        ),
    }),
    versionedMutationRoute({
      method: 'PUT',
      pattern: '/notebook/bookmarks/:id',
      metric: 'UpdateBookmark',
      oversizedBody413: true,
      params: IdParams,
      body: UpdateBookmarkRequestSchema,
      mutate: (ctx, { params, body, expected }) =>
        bookmarks().updateFromRequest(ctx.userId!, params.id, expected, body),
      respond: parseBookmark,
    }),
    versionedMutationRoute({
      method: 'DELETE',
      pattern: '/notebook/bookmarks/:id',
      metric: 'DeleteBookmark',
      params: IdParams,
      body: ExpectedVersionRequestSchema.partial(),
      mutate: (ctx, { params, expected }) =>
        bookmarks().deleteIfVersion(ctx.userId!, params.id, expected),
      respond: parseBookmark,
    }),
  ];
}

export const bookmarkRoutes: RouteDef[] = createBookmarkRoutes();
```

Route patterns omit the `/api` prefix. Put literal segments (`/:id/archive`) before `/:id`. `versionedMutationRoute` also takes a `precheck` that can return an early response after the version check (tasks use it to validate `noteId`), and a `withoutVersion` handler for writes that may arrive with no version (the daily note PUT creates the day's note through it).

## Publishable site entity

An admin-edited entity with a draft `META` row, a `PUBLISHED` snapshot, a URL
slug and static pages written by the publisher. Projects are the smallest
complete example (`project` below); posts add tags and feeds on top. The
entity gets:

- `/api/admin/<things>` list / create, `/{id}` get / update / soft delete, `/{id}/publish`, `/unpublish`, `/discard`, all `auth: 'site-admin'`, `version` in the body
- a slug claim that is unique per entity type, with rename redirects
- publisher pages at `/<things>` and `/<things>/<slug>`, rebuilt only when a `PUBLISHED` row changes, plus sitemap entries
- restore-test schema checks and a count floor

There is no public API: the read side is static HTML in S3.

### Data

- **Publish status vs domain status.** Every publishable entity has `status: draft | published | deleted`. Name any domain lifecycle field something else (projects use `stage`).
- **Own GSI1 partition.** META carries `gsi1pk = <THING>_STATUS#<status>`, never posts' `STATUS#…`, so `listPublishedPosts` needs no `entityType` filter. Choose `gsi1sk` for the admin list order (projects: `ORDER#<6 digits>#PROJECT#<id>`). `build…PublishedItem` drops the GSI1 keys so only META rows are on the index.
- **Own slug partition.** Claims are `<THING>_SLUG#<slug>` / `<THING>` and redirects `<THING>_SLUG#<old>` / `REDIRECT`. A shared `SLUG#` partition would collide on `REDIRECT`. Add a `SlugClaims` entry in `data/slug-claims.ts` and pass it as the repository's `slugClaims`.

### Repository and routes

Extend `PublishableRepository` with `keysFor`, `toEntity`, `toItem`, `toPublishedItem`, `contentEqual`, `isDeleted` and `slugClaims`, and pass the constructor's `now` clock through. The base owns every write: `insertDraft` (slug claim + META with `attribute_not_exists`), `mutate` (consistent read, version check, `updatedAt` from the clock), `softDelete`, `publish`, `unpublish` and `discard`. Each mutation is one transaction with the version-conditioned META Put at index 0, the slug rename rows, the `PUBLISHED` put or delete and the soft-delete slug release, so a taken slug is `slug_taken` and a stale version wins with `current`. Use `validatePublish` for rules a draft must meet before it goes live and `extraMutationItems` for rows that change with it (posts write tag-index rows there). `create` builds the entity and calls `insertDraft`; `update` passes a field merge to `mutate`. The META row stores `hasUnpublishedChanges` (have `toItem` write it and `toPublishedItem` drop it). Lists page with `queryListPage` (and `walkPartitions` across status partitions), passing `attributes` to read summary fields with a `ProjectionExpression` and a `parse` that leaves the flag undefined when the row has none, so only those rows are compared with `PUBLISHED`; `existingIds` checks many ids with one BatchGet.

Declare `GET` routes with `defineRoute` and `getByIdOrThrow` (404 from `NotFoundError`), and every versioned write (`PUT`, `DELETE`, `publish`, `unpublish`, `discard`) with `siteAdminVersionedRoute` from `data/versioned-route.ts`: body `version` (default body `ExpectedVersionRequestSchema`) → `mutate` → 200 with the entity parsed through `entity`. Metric names are `<Verb><Thing>` (`PublishProject`); singletons pass `metricName` to `createSingletonRoutes`.

Routes live under `/admin/<things>` with `auth: 'site-admin'`; ids are `UlidSchema`. `test/router.test.ts` checks that every `/admin` route outside `/admin/users` is `site-admin` and that routes and OpenAPI operations match one to one; add an explicit list for the new prefix like the projects one. Validate any user-supplied link with `isSafeLinkHref` (`packages/shared/src/links.ts`): `POST_LINK_SCHEMES` is what the markdown sanitizer keeps in post bodies.

### Publisher

The target matches `touchedEntityTypes.has('<thing>') || isFullRebuildScope(scope)`, loads its catalog only when it matches (projects add `needsProjects` to `PublishTarget` and `listPublishedProjects` to the sources), declares `optionBPaths: ['/<things>']`, `adminMutationPrefixes: ['/api/admin/<things>']` and `adminSoftDelete: true`, and returns artifacts for the index and each page plus `deleteKeys` for pages that should no longer exist (list `<things>/` and keep corrupt rows' pages). Run `npm run publish-surface:generate` so the viewer-request function serves `/<things>`. It serves nothing under that path on its own: CloudFront skips viewer-response on an S3 4xx, so an unknown `/<things>/<slug>` would be raw S3 XML. Give the slugs a KeyValueStore namespace as projects do (`PROJECT_SLUG_NAMESPACE` in `services/publisher/src/viewer-request-slugs.ts`, its sync in the orchestrator, and the matching `childSlug` branch in `infra/lib/cloudfront/viewer-request-function.js`). Extend `buildSitemapXml` and the `sitemap` target instead of writing `sitemap.xml` from the new target.

### Admin

The admin list follows Projects: `useProjectsQuery` (the list endpoint returns every row, so it is a plain query, not an infinite one). `setCachedProject` updates a fetched list but never seeds an unfetched one.

The editor is built from the shared pieces in `apps/web/src/admin/editor/`, as `ProjectEditorPage.tsx` shows:

- **`<thing>Draft.ts`**: the draft type, `empty<Thing>Draft`, `<thing>DraftFromX` and the payload builder `<thing>Payload(draft, saved)`. Put field validation here too, so the page and its tests share it.
- **`useAdminEntityEditor`**: the resource (`projectResource`), draft mappers and payload builder, the confirm texts, a `subject` for the conflict message ("this project"), `uniqueSlug` for the slug-taken message, and `delete: { confirm, mutate, redirectTo }`.
- **`useDraftFields(editor, { slugFrom: 'name' })`**: `setField` (a value or an updater) and `setSlugManual`. With `slugFrom`, the slug follows that field until the Slug input is edited; a loaded entity whose slug is still a placeholder (`placeholderSlug.ts`) keeps following.
- **`EditorFrame`**: the load-error, loading and save-error states, the action bar with View live and Delete, and `notices` for page-specific alerts. Render the form in its `children(entity)`; `EditorNotice` is the missing-id panel.
- **`useImageUpload(editor.setSaveError)`**: `uploadImage` for an `ImageUploadField` (its errors show under the field) and `uploadBodyImages` for `MarkdownBodyEditor` (its errors show as the save error). Both upload to `/media` through `uploadImages`.
- **Widgets**: `ChipsInput` for list-of-strings fields, `ImageUploadField` (`dropzone` or `thumbnail`), `SegmentedRadio` (`workspace/ui`) for a small enum, and `BodyPreview` for a markdown body rendered as its public page.

`e2e/tests/admin-projects.spec.ts` drives create, edit, upload, publish, unpublish, delete and a slug conflict through the admin against the local publisher.

The CloudFront function change and the IAM change deploy with CDK. Add the new `LeadingKeys` to `infra/test/publisher-iam.test.ts`, which evaluates the synthesized policy and also proves `USER#…` stays unreadable.
