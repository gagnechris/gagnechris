# Adding an entity

Two kinds: a synced, owner-scoped Notebook entity (below), and a
[publishable site entity](#publishable-site-entity) with a draft, a live
snapshot and static public pages (like posts and projects).

How to add a synced, owner-scoped, versioned Notebook entity (like notes and tasks) to the API. The examples use a `bookmark` entity with `url` and `title`; replace the names.

The entity gets:

- `GET/POST /api/notebook/bookmarks`, `GET/PUT/DELETE /api/notebook/bookmarks/{id}`
- optimistic concurrency (`version`, `If-Match` / `ETag`, 409 / 412), client-ULID idempotent create, soft delete
- a `bookmark` change type in `GET /api/notebook/sync/changes`
- OpenAPI types in `@gagnechris/api-client` and `services/api/internal/apitypes`

No new GSI, table, or infra change is needed: META rows live in the existing table, the sync GSI is shared, and API Gateway already sends every `/api/notebook/*` path to the Go API.

The contract is defined in TypeScript (wire schemas, keys, stored rows) and the API is Go. `scripts/generate-go-contract.ts` writes the TypeScript side into `services/api/internal/contract/contract.json`, and Go tests hold the Go keys, sync adapters and restore-test rules to it.

## 1. Wire schemas — `packages/shared/src/schemas.ts`

Add the entity, list response, create / update / list-query schemas, and a sync change variant. Add the variant to `SyncChangeSchema`; `SYNC_CHANGE_TYPES` is derived from it.

```ts
export const BookmarkSchema = z.object({
  id: UlidSchema,
  userId: z.string().min(1),
  url: z.string().url(),
  title: NotebookTitleSchema,
  version: VersionSchema,
  createdAt: z.string().datetime({ offset: true }),
  updatedAt: z.string().datetime({ offset: true }),
  deleted: z.boolean(),
});
export type Bookmark = z.infer<typeof BookmarkSchema>;

export const BookmarkListResponseSchema = z.object({
  items: z.array(BookmarkSchema),
  nextCursor: z.string().min(1).optional(),
});

export const CreateBookmarkRequestSchema = z.object({
  id: UlidSchema,
  url: z.string().url(),
  title: NotebookTitleSchema.default(''),
});
export type CreateBookmarkRequest = z.infer<typeof CreateBookmarkRequestSchema>;

// `version` is optional because `If-Match` can carry it instead.
export const UpdateBookmarkRequestSchema = z.object({
  version: VersionSchema.optional(),
  url: z.string().url().optional(),
  title: NotebookTitleSchema.optional(),
});
export type UpdateBookmarkRequest = z.infer<typeof UpdateBookmarkRequestSchema>;

export const ListBookmarksQuerySchema = z.object({
  cursor: z.string().min(1).optional(),
  limit: PageLimitSchema.optional(),
});
export type ListBookmarksQuery = z.infer<typeof ListBookmarksQuerySchema>;

export const BookmarkSyncChangeSchema = syncChangeSchemaFor(
  'bookmark',
  BookmarkSchema,
);

export const SyncChangeSchema = z.discriminatedUnion('type', [
  NoteSyncChangeSchema,
  TaskSyncChangeSchema,
  BookmarkSyncChangeSchema,
]);
```

Declare `BookmarkSchema` after `NotebookTitleSchema` / `NotebookTextSchema` (they are `const`s, not hoisted). Request text fields use `NotebookTextSchema` / `NotebookTitleSchema` / `NotebookTagsSchema` so oversized fields return 413. These schemas are the contract: the Go handlers validate requests to the same rules (step 9).

## 2. OpenAPI — `packages/shared/src/openapi.ts`

Import the schemas, register the named components next to the other Notebook ones, add the sync variant to the registered `SyncChange` union (each variant is registered inside it so it is a `$ref`; an inlined union nested in a union generates no usable Go type), and register the paths:

```ts
registry.register('Bookmark', BookmarkSchema);
registry.register('BookmarkListResponse', BookmarkListResponseSchema);
registry.register('CreateBookmarkRequest', CreateBookmarkRequestSchema);
registry.register('UpdateBookmarkRequest', UpdateBookmarkRequestSchema);
registry.register('ListBookmarksQuery', ListBookmarksQuerySchema);

const syncChange = registry.register(
  'SyncChange',
  z.discriminatedUnion('type', [
    registry.register('NoteSyncChange', NoteSyncChangeSchema),
    registry.register('TaskSyncChange', TaskSyncChangeSchema),
    registry.register('BookmarkSyncChange', BookmarkSyncChangeSchema),
  ]),
);

registerNotebookEntityPaths(registry, {
  path: '/api/notebook/bookmarks',
  noun: 'bookmark',
  entity: BookmarkSchema,
  listQuery: ListBookmarksQuerySchema,
  listResponse: BookmarkListResponseSchema,
  createRequest: CreateBookmarkRequestSchema,
  updateRequest: UpdateBookmarkRequestSchema,

```

`registerNotebookEntityPaths` registers list, create, get, update (with `If-Match`), and soft delete with the standard responses. Paths beyond those go in `extraPaths` (see the notes and tasks calls).

Then run `npm run openapi` to regenerate `packages/shared/openapi/openapi.json`, `packages/api-client/src/schema.d.ts`, the Go API types in `services/api/internal/apitypes` and `services/api/internal/contract/contract.json`.

## 3. Keys — `packages/data/src/keys.ts`

```ts
export function bookmarkPk(userId: string, bookmarkId: string): string {
  return `USER#${userId}#BOOKMARK#${bookmarkId}`;
}

/** GSI1 list partition: one per user. */
export function bookmarksGsi1Pk(userId: string): string {
  return `USER#${userId}#BOOKMARKS`;
}

export function bookmarkGsi1Sk(updatedAt: string, bookmarkId: string): string {
  return `UPDATED#${updatedAt}#BOOKMARK#${bookmarkId}`;
}
```

Key strings come only from these functions and their Go copies (step 6). An item key (`{ pk, sk }`) comes only from `keys`, so add one under `keys.notebook`:

```ts
bookmark: {
  meta: (userId: string, id: string) => ({
    pk: bookmarkPk(userId, id),
    sk: SK_META,
  }),
},
```

Partition keys start with `USER#<sub>#` so rows are owner-scoped. Lists use the existing `gsi1pk`/`gsi1sk` (or `gsi2pk`/`gsi2sk`) attributes, namespaced by `USER#<sub>#` so they never share a partition with posts or other users. `build…MetaItem` (and its Go copy) must leave these four attributes off a tombstone (see `buildTaskMetaItem` and `taskItem`) so lists never return deleted rows; the store does not strip them.

## 4. Stored item — `packages/data/src/items.ts`

```ts
export const BookmarkMetaItemSchema = VersionedMetaFieldsSchema.extend({
  pk: z.string().min(1),
  sk: z.string().min(1),
  entityType: z.literal('bookmark'),
  id: z.string().min(1),
  userId: z.string().min(1),
  url: z.string(),
  title: z.string(),
});
export type BookmarkMetaItem = z.infer<typeof BookmarkMetaItemSchema>;

export function parseBookmarkMetaItem(raw: unknown): BookmarkMetaItem {
  return BookmarkMetaItemSchema.parse(raw);
}

export function metaToBookmark(item: BookmarkMetaItem): Bookmark {
  return {
    id: item.id,
    userId: item.userId,
    url: item.url,
    title: item.title,
    version: item.version,
    createdAt: item.createdAt,
    updatedAt: item.updatedAt,
    deleted: item.deleted,
  };
}

export function buildBookmarkMetaItem(b: Bookmark): BookmarkMetaItem {
  return {
    ...keys.notebook.bookmark.meta(b.userId, b.id),
    entityType: 'bookmark',
    id: b.id,
    userId: b.userId,
    url: b.url,
    title: b.title,
    version: b.version,
    createdAt: b.createdAt,
    updatedAt: b.updatedAt,
    deleted: b.deleted,
    ...(b.deleted
      ? {}
      : {
          gsi1pk: bookmarksGsi1Pk(b.userId),
          gsi1sk: bookmarkGsi1Sk(b.updatedAt, b.id),
        }),
  };
}
```

Add a `bookmarkContentEqual(a, b)` beside `taskContentEqual` for the copy-back (step 13).

`VersionedMetaFieldsSchema` already allows `version`, timestamps, `deleted`, `createHash`, sync keys, `ttl`, and the GSI1/GSI2 attributes. Sync keys, `createHash`, and `ttl` are written by the Go store, not by the row builder. Import `Bookmark` from `@gagnechris/shared` and `keys`, `bookmarksGsi1Pk`, `bookmarkGsi1Sk` from `./keys.js`.

These builders define the stored row. The Go API writes the same rows (step 7), and the copy-back (step 13) reads and writes them in TypeScript, so the two must match field for field.

## 5. Contract — `scripts/generate-go-contract.ts`

- **`KEYS`**: one entry per key builder, with braced placeholders that Go fills with the same values: `'bookmarkPk({userId},{bookmarkId})': bookmarkPk('{userId}', '{bookmarkId}')`, plus `bookmarksGsi1Pk({userId})` and `bookmarkGsi1Sk({updatedAt},{bookmarkId})`.
- **`ITEM_SCHEMAS`** (in `packages/data/src/items.ts`): `bookmark: BookmarkMetaItemSchema`. It is typed by `RESTORE_TEST_SCHEMA_CHECKED_ENTITY_TYPES`, so typecheck fails until it has an entry for each type step 12 adds. The generator and the HTTP suite's row check both read it.
- **`SAMPLES`**: a `bookmark` row from `buildBookmarkMetaItem`. The generator refuses a sample that does not parse with its item schema, and the restore-test validator's tests check every sample. List the sample in `Builders` in `services/api/internal/contract/samplerows` (here `"bookmark": "notebook"`) and extend the rebuild in `services/api/internal/notebook/samples_test.go` to parse it and rebuild it with `bookmarkItem`, which must give back the sample exactly; `TestEverySampleHasABuilderOrASkipReason` fails until the sample is in `Builders` or, with a reason, in `Skipped`.
- **`API_SAMPLES`**: a `bookmark` body (`BookmarkSchema`) and a `syncBookmark` change (`SyncChangeSchema`). Add both to the round trips in `services/api/internal/apitypes/apitypes_test.go`, which prove the generated Go types carry every field.

Run `npm run go:generate` (or `npm run openapi`); `npm run go:generate:check` fails while `contract.json` or `apitypes.gen.go` is stale.

## 7. Go struct and row — `services/api/internal/notebook`

In `items.go`, the API shape and the row mappers, mirroring `metaToBookmark`, `parseBookmarkMetaItem` and `buildBookmarkMetaItem`:

```go
// Bookmark is the API's Bookmark, in BookmarkSchema's field order.
type Bookmark struct {
	ID        string `json:"id"`
	UserID    string `json:"userId"`
	URL       string `json:"url"`
	Title     string `json:"title"`
	Version   int    `json:"version"`
	CreatedAt string `json:"createdAt"`
	UpdatedAt string `json:"updatedAt"`
	Deleted   bool   `json:"deleted"`
}

func ParseBookmark(item data.Item) (Bookmark, error) {
	r := store.ReadItem(item)
	r.Str("pk", 1)
	r.Str("sk", 1)
	r.Literal("entityType", "bookmark")
	b := Bookmark{
		ID:     r.Str("id", 1),
		UserID: r.Str("userId", 1),
		URL:    r.Str("url", 0),
		Title:  r.Str("title", 0),
	}
	b.Version, b.CreatedAt, b.UpdatedAt, b.Deleted = versionedMeta(r)
	return b, r.Err("bookmark")
}

// bookmarkItem is buildBookmarkMetaItem: a tombstone leaves the list index.
func bookmarkItem(b Bookmark) data.Item {
	item := data.Key(keys.BookmarkPk(b.UserID, b.ID), keys.SKMeta)
	item["entityType"] = data.S("bookmark")
	item["id"] = data.S(b.ID)
	item["userId"] = data.S(b.UserID)
	item["url"] = data.S(b.URL)
	item["title"] = data.S(b.Title)
	item["version"] = data.N(int64(b.Version))
	item["createdAt"] = data.S(b.CreatedAt)
	item["updatedAt"] = data.S(b.UpdatedAt)
	item["deleted"] = data.Bool(b.Deleted)
	if !b.Deleted {
		item["gsi1pk"] = data.S(keys.BookmarksGSI1Pk(b.UserID))
		item["gsi1sk"] = data.S(keys.BookmarkGSI1Sk(b.UpdatedAt, b.ID))
	}
	return item
}
```

`versionedMeta` reads `VersionedMetaFieldsSchema`'s fields. In `apicheck.go`, add a `checkBookmark` that holds a stored row to `BookmarkSchema` beyond what the row schema checks (a ULID `id`, ISO datetimes, the URL), as `checkTask` does; responses and sync changes run through it. In `versioned.go`, give `*Bookmark` the `entity` methods (`ident`, `ver`, `setVersion`, `updated`, `isDeleted`) next to Note's and Task's.

## 8. Repository — `services/api/internal/notebook/bookmarks.go`

Wrap the generic `versioned` store (`versioned.go`). Concurrency, idempotent create (create claim + `createHash`), sync stamping (`entityType`, `syncPk`, `syncSk`), tombstone TTL and soft delete come from it; the wrapper builds entities from requests.

```go
package notebook

const bookmarkChangeType = "bookmark"

func bookmarkKey(userID, id string) data.Item {
	return data.Key(keys.BookmarkPk(userID, id), keys.SKMeta)
}

func bookmarkCreateHash(b Bookmark) string {
	return hashCreateFields(b.UserID, b.URL, b.Title)
}

type bookmarksRepo struct {
	table *data.Table
	base  *versioned[Bookmark, *Bookmark]
}

func newBookmarksRepo(table *data.Table, now func() time.Time) *bookmarksRepo {
	return &bookmarksRepo{table: table, base: &versioned[Bookmark, *Bookmark]{
		table: table, now: now, label: "bookmark", changeType: bookmarkChangeType,
		key: bookmarkKey, parse: ParseBookmark, item: bookmarkItem, createHash: bookmarkCreateHash,
	}}
}

func (r *bookmarksRepo) create(ctx context.Context, userID, id, url, title string) (Bookmark, error) {
	now := r.base.nowISO()
	return r.base.createIdempotent(ctx, Bookmark{
		ID: id, UserID: userID, URL: url, Title: title,
		Version: 1, CreatedAt: now, UpdatedAt: now,
	})
}

func (r *bookmarksRepo) update(ctx context.Context, userID, id string, expected api.Expected, url, title *string) (Bookmark, error) {
	return r.base.mutate(ctx, userID, id, expected, func(b Bookmark, now string) (Bookmark, error) {
		setIf(&b.URL, url)
		setIf(&b.Title, title)
		b.UpdatedAt = now
		return b, nil
	})
}

func (r *bookmarksRepo) delete(ctx context.Context, userID, id string, expected api.Expected) (Bookmark, error) {
	return r.base.softDelete(ctx, userID, id, expected, func(b Bookmark, now string) Bookmark {
		b.UpdatedAt = now
		b.Deleted = true
		return b
	})
}

func (r *bookmarksRepo) list(ctx context.Context, userID, cursor string, limit int, onCorrupt func(*api.DataIntegrityError)) (store.Page[Bookmark], error) {
	return gsi1Page(ctx, r.table, keys.BookmarksGSI1Pk(userID), nil, cursor, limit, store.PageByteBudget,
		ParseBookmark, func(b Bookmark) bool { return b.Deleted }, nil, onCorrupt)
}
```

`gsi1Page` binds the cursor to the queried partition, so a cursor from another partition is a 400. `tasks.go` is the full example.

Store options worth knowing:

- `claim` — a `uniqueClaim`: an extra uniqueness row in the create transaction, with conflict resolution and release on delete (daily notes use it for the day).
- `now` — the only clock (`Routes(table, now)`, `time.Now` when nil); create, update and tombstone timestamps come from it.
- `store.WalkPartitions` — one cursor across several partitions (tasks page across area × status).

## 9. Routes — `services/api/internal/notebook/routes.go`

Add `bookmarks *bookmarksRepo` to `handlers`, construct it in `Routes`, and add the routes:

```go
route(http.MethodGet, "/notebook/bookmarks", "ListBookmarks", h.listBookmarks),
route(http.MethodPost, "/notebook/bookmarks", "CreateBookmark", h.createBookmark),
route(http.MethodGet, "/notebook/bookmarks/:id", "GetBookmark", h.getBookmark),
route(http.MethodPut, "/notebook/bookmarks/:id", "UpdateBookmark", h.updateBookmark),
route(http.MethodDelete, "/notebook/bookmarks/:id", "DeleteBookmark", h.deleteBookmark),
```

The handlers read the body with `api.Validator` to the zod schema's rules, in its field order, so the 400 lists the same issues. The package's helpers cover the Notebook schemas: `title` and `text` (`NotebookTitleSchema`, `NotebookTextSchema`), `tags`, `idParam`, `bodyVersion`, `expected` (resolves `If-Match` / `body.version`; 400 when a required one is missing), `versionOnly` for writes that take only a version, `pageLimit` and `listResponse`.

```go
func bookmarkResponse(status int, b Bookmark) (*api.Response, error) {
	if err := checkBookmark(b); err != nil {
		return nil, err
	}
	return api.JSONWithETag(status, b, b.Version), nil
}

func (h handlers) createBookmark(ctx context.Context, r *api.Request) (*api.Response, error) {
	v, err := api.NewValidator(r.Body)
	if err != nil {
		return nil, err
	}
	id, _ := v.ULID("id", true)
	url, _ := v.String("url", true, false, api.Refine(isURL))
	t, _ := title(v, "title", 0, false)
	if err := v.ErrMaybeTooLarge(); err != nil {
		return nil, err
	}
	b, err := h.bookmarks.create(ctx, r.UserID(), id, url, t)
	if err != nil {
		return nil, err
	}
	return bookmarkResponse(http.StatusCreated, b)
}

func (h handlers) updateBookmark(ctx context.Context, r *api.Request) (*api.Response, error) {
	v, err := api.NewValidator(r.Body)
	if err != nil {
		return nil, err
	}
	version := bodyVersion(v)
	url := optStr(v.String("url", false, false, api.Refine(isURL)))
	t := optStr(title(v, "title", 0, false))
	if err := v.ErrMaybeTooLarge(); err != nil {
		return nil, err
	}
	id, err := idParam(r)
	if err != nil {
		return nil, err
	}
	e, err := expected(r, version, true)
	if err != nil {
		return nil, err
	}
	b, err := h.bookmarks.update(ctx, r.UserID(), id, e, url, t)
	if err != nil {
		return nil, e.IfMatchConflict(err)
	}
	return bookmarkResponse(http.StatusOK, b)
}
```

`isURL` stands for a check matching zod's `.url()`. `ErrMaybeTooLarge` is the 400, or a 413 when only size limits failed. `e.IfMatchConflict` makes a conflict on an `If-Match` write a 412 (409 otherwise); a conflict body carries the current entity. Delete is `versionOnly` → `h.bookmarks.delete` → `e.IfMatchConflict`, as `taskAction` does; list reads `cursor` and `pageLimit` from `api.NewQueryValidator(r.Query)` and returns `listResponse(page, checkBookmark)`, with `store.LogCorrupt(r.Log, r.Metrics)` as `onCorrupt`.

Route patterns omit the `/api` prefix; `:id` takes one segment, and a literal segment beats a parameter. Every `/notebook` route is `api.Notebook`: `api.NewRouter` panics on a route whose `Auth` is not the one its prefix requires (`RequiredAuth`). Metric names are `<Verb><Thing>`.

## 11. Test — `services/api/test/http/bookmarks.test.ts`

The HTTP suite runs against the built Go API on DynamoDB Local. `useApi('bookmarks')` (`test/http/support/harness.ts`) gives the file its own table and server; send requests with `h.api.request(method, path, { body, headers, claims: notebookUser(sub) })` and use `h.doc` / `h.tableName` to seed or read rows. Cover at least: create (201 + `ETag: "1"`), idempotent re-create and a different body under the same id (409), update with `If-Match`, a stale `If-Match` (412), delete, owner isolation, a 413 for an oversized title, and the `bookmark` change in `GET /api/notebook/sync/changes`. Check that rows match the TypeScript builders: read a stored row with `h.doc` and parse it with `parseBookmarkMetaItem`, and seed a `buildBookmarkMetaItem` row and read it through the API. The harness also parses every 2xx body with the response schema the OpenAPI document declares for its route and status, and after each test every row in the table with its entity type's `ITEM_SCHEMAS` entry, so the routes must be registered in `openapi.ts` before the suite passes; a test that stores a corrupt row on purpose calls `h.corruptRow(key)` first. `tasks.test.ts` and `tasks-parity.test.ts` are full examples.

## 12–14. Restore test, copy-back and search

A synced type has to be covered in three more places, or the weekly restore test, "restore my notes" and search silently skip it. `packages/ops/test/synced-type-coverage.test.ts` fails until every `SYNC_CHANGE_TYPES` entry is in all of them:

- **Copy-back** (`packages/ops/src/copy-back.ts`): add `'bookmark'` to `COPY_BACK_TYPES`, then the `KEY_FOR`, `parseEntity`, `contentEqual`, `typeOfItem`, `scanSourceRows` prefix and `storedItem` builder branches (`contentEqual` uses `bookmarkContentEqual` from step 4). ## Publishable site entity

An admin-edited entity with a draft `META` row, a `PUBLISHED` snapshot, a URL
slug and static pages written by the publisher. Projects are the smallest
complete example (`project` below); posts add tags and feeds on top. The
entity gets:

- `/api/admin/<things>` list / create, `/{id}` get / update / soft delete, `/{id}/publish`, `/unpublish`, `/discard`, all `site-admin`, `version` in the body
- a slug claim that is unique per entity type, with rename redirects
- publisher pages at `/<things>` and `/<things>/<slug>`, rebuilt only when a `PUBLISHED` row changes, plus sitemap entries
- restore-test schema checks and a count floor

There is no public API: the read side is static HTML in S3. API Gateway already sends every `/api/admin/*` path to the Go API.

### Data

- **Publish status vs domain status.** Every publishable entity has `status: draft | published | deleted`. Name any domain lifecycle field something else (projects use `stage`).
- **Own GSI1 partition.** META carries `gsi1pk = <THING>_STATUS#<status>`, never posts' `STATUS#…`, so the posts query never reads it; the publisher's `listPublishedPosts` and `listPublishedProjects` still skip any row whose `entityType` isn't theirs. Choose `gsi1sk` for the admin list order (projects: `ORDER#<6 digits>#PROJECT#<id>`). The published row builder drops the GSI1 keys so only META rows are on the index.
- **Own slug partition.** Claims are `<THING>_SLUG#<slug>` / `<THING>` and redirects `<THING>_SLUG#<old>` / `REDIRECT`. A shared `SLUG#` partition would collide on `REDIRECT`. The Go config's `store.SlugClaims` names these keys, the owner attribute and the claim and redirect entity types (projects' `slugClaims` in `services/api/internal/projects/project.go`).
- **Rows are defined in TypeScript.** The `@gagnechris/data` builders are the stored row; the publisher reads rows the Go API writes, so the Go `metaItem` / `publishedItem` must match them field for field. Add the keys to `KEYS` and samples from `build…MetaItem` and `build…PublishedItem` to `SAMPLES` in `scripts/generate-go-contract.ts`, list those samples in `Builders` in `services/api/internal/contract/samplerows` with a `samples_test.go` in the Go package that rebuilds them through `parse` and `metaItem` / `publishedItem` (as in `projects`), the Go key builders to `services/api/internal/keys` (checked against the contract by `keys_test.go`), and a `keyRules` entry in `services/api/internal/restoretest/validate.go`.

### Repository and routes

Create a package under `services/api/internal/<things>` (`services/api/internal/projects` is the example) whose `Routes(table, now)` builds a `store.NewPublishableStore` from a `store.PublishableConfig`: `Label`, `Keys` (the META and `PUBLISHED` keys for an id), `ID`, `State` (the embedded `store.Publishable`), `Parse`, `MetaItem`, `PublishedItem`, `ContentEqual`, `Slug`, `SlugClaims` and `PublishedIDSet` (`"<thing>Ids"`, the site publish row's id set). The store owns every write: `InsertDraft` (slug claim + META with `attribute_not_exists`), `Mutate` (consistent read, version check, `version` and `updatedAt` from the clock, the unpublished flag), `SoftDelete`, `Publish`, `Unpublish` and `Discard`. Each mutation is one transaction with the version-conditioned META Put at index 0, the slug rename rows, the `PUBLISHED` put or delete, the site publish row update and the soft-delete slug release, so a taken slug is `slug_taken` and a stale version is a 409 with `current`. Use `ValidatePublish` for rules a draft must meet before it goes live. `create` builds the entity and calls `InsertDraft`; `update` passes a field merge to `Mutate`. The META row stores `hasUnpublishedChanges` (have `MetaItem` write it and `PublishedItem` drop it). Lists page with `store.QueryListPage` (and `store.WalkPartitions` across status partitions) and a `store.ListSpec`: `Attributes` reads summary fields with a `ProjectionExpression`, and `StoredFlag` returns nil when the row has no stored flag, so only those rows are compared with `PUBLISHED`. A `Where` predicate filters in the API; pair it with `PageQuery.MaxItems` and a larger `Limit` so a page fills. `store.Singleton` and `store.SingletonRoutes` cover a singleton like Home.

Register the routes with `api.SiteAdmin` and metric names `<Verb><Thing>` (`PublishProject`), and append the package's `Routes(table, nil)` in `services/api/cmd/api/main.go`. Every versioned write (`PUT`, `DELETE`, `publish`, `unpublish`, `discard`) reads a required body `version` (projects' `versioned` helper); `GET` uses `GetOrThrow` (404 when missing). Ids are ULIDs (projects' `idParam`). `api.NewRouter` panics on a route under `/admin` (outside `/admin/users`) that is not `api.SiteAdmin`. Validate user-supplied links like `isSafeLinkHref` (`packages/shared/src/links.ts`): projects' `safeHref` (`services/api/internal/projects/links.go`) is its Go copy, with `TestSafeHrefMatchesShared` holding it to the TypeScript results; `POST_LINK_SCHEMES` is what the markdown sanitizer keeps in post bodies. Limits come from the contract (`contract.Data.Limits`).

Cover the routes in `services/api/test/http/<things>.test.ts` (`projects-admin.test.ts` and `publishable.test.ts` are examples; `siteAdminClient` in `test/http/support/site-admin.ts` wraps the calls), including a row read back and parsed with the TypeScript item schema, since the publisher reads it.

### Publisher

The target matches `touchedEntityTypes.has('<thing>') || isFullRebuildScope(scope)`, declares what it reads in `needs` (`posts`, `shell`, `projects`; the orchestrator loads only what an active target needs; a new kind of row needs its own source, as `listPublishedProjects` is for projects), builds pages with `htmlArtifact` / `jsonArtifact` (`publish-targets/artifacts.ts`), declares `optionBPaths: ['/<things>']`, `s3Outputs: ['<things>/*']` (every key it writes or deletes; `publish-surface:generate` writes them to `scripts/publisher-owned-paths.generated.txt`, which keeps web deploys and the local seed from deleting them), `adminMutationPrefixes: ['/api/admin/<things>']` and `adminSoftDelete: true`, and returns artifacts for the index and each page plus `deleteKeys` for pages that should no longer exist (list `<things>/` and keep corrupt rows' pages). Run `npm run publish-surface:generate` so the viewer-request function serves `/<things>`. It serves nothing under that path on its own: CloudFront skips viewer-response on an S3 4xx, so an unknown `/<things>/<slug>` would be raw S3 XML. Give the slugs a KeyValueStore namespace as projects do: its key prefix and sentinel in `packages/shared/src/slug-kvs.ts` (emitted into the viewer-request function by `publish-surface:generate`), a namespace in `services/publisher/src/viewer-request-slugs.ts` (`PROJECT_SLUG_NAMESPACE`), the target's `kvs` (namespace, page prefix and how page keys become KVS keys; the orchestrator syncs it after the last pass), and the matching `childSlug` branch in `infra/lib/cloudfront/viewer-request-function.js`. Extend `buildSitemapXml` and the `sitemap` target instead of writing `sitemap.xml` from the new target.

### Admin

The admin list follows Projects: `useProjectsQuery` (the list endpoint returns every row, so it is a plain query, not an infinite one). `setCachedProject` updates a fetched list but never seeds an unfetched one.

The editor is built from the shared pieces in `apps/web/src/admin/editor/`, as `ProjectEditorPage.tsx` shows:

- **`<thing>Draft.ts`**: the draft type, `empty<Thing>Draft`, `<thing>DraftFromX` and the payload builder `<thing>Payload(draft, saved)`. Put field validation here too, so the page and its tests share it.
- **`useAdminEntityEditor`**: the resource (`projectResource`), draft mappers and payload builder, the confirm texts, a `subject` for the conflict message ("this project"), `uniqueSlug` for the slug-taken message, and `delete: { confirm, mutate, redirectTo }`.
- **`useDraftFields(editor, { slugFrom: 'name' })`**: `setField` (a value or an updater) and `setSlugManual`. With `slugFrom`, the slug follows that field until the Slug input is edited; a loaded entity whose slug is still a placeholder (app-core's `isPlaceholderSlug`) keeps following.
- **`EditorFrame`**: the load-error, loading and save-error states, the action bar with View live and Delete, and `notices` for page-specific alerts. Render the form in its `children(entity)`; `EditorNotice` is the missing-id panel.
- **`useImageUpload(editor.setSaveError)`**: `uploadImage` for an `ImageUploadField` (its errors show under the field) and `uploadBodyImages` for `MarkdownBodyEditor` (its errors show as the save error). Both go through `uploadImages`: a presigned URL from `POST /api/admin/media/upload-url`, then a `PUT` of the file.
- **Widgets**: `ChipsInput` for list-of-strings fields, `ImageUploadField` (`layout: 'dropzone' | 'thumbnail'`), `SegmentedRadio` (`workspace/ui`) for a small enum, and `MarkdownBodyEditor` (`kit/markdown`) with a `LazyBodyPreview` that renders the body as its public page. Projects keep the form fields in `ProjectEditorFields.tsx`.

`e2e/tests/admin-projects.spec.ts` drives create, edit, upload, publish, unpublish, delete and a slug conflict through the admin against the local publisher; `admin-post-flows.spec.ts` does the same for posts and adds Publish changes, Discard changes, a two-tab conflict, ⌘⏎ in the body and the leave guard.

The CloudFront function change and the IAM change deploy with CDK. Add the new `LeadingKeys` to `infra/test/publisher-iam.test.ts`, which evaluates the synthesized policy and also proves `USER#…` stays unreadable.
